# Правила работы над Workout Tracker

## Источник требований

- Спецификация MVP находится в `docs/PROJECT_SPEC.md`.
- Не добавляй функции вне MVP без явного решения пользователя.
- Если требование неоднозначно или влияет на модель данных/API, сначала зафиксируй решение в спецификации.

## Принципы разработки

- Делай небольшие, проверяемые изменения.
- Перед написанием функционала сначала определи пользовательский сценарий, данные и критерий готовности.
- Не храни пароли, токены и другие секреты в репозитории.
- Используй миграции для изменений схемы базы данных.
- Покрывай критичные пользовательские сценарии тестами по мере появления тестовой инфраструктуры.
- Объясняй новые технологии кратко и в контексте задачи, чтобы проект оставался учебным.

## Структура документации

- `README.md` — краткое описание проекта и инструкция по запуску.
- `docs/PROJECT_SPEC.md` — продуктовые требования MVP.
- `docs/DECISIONS.md` — принятые технические решения и их причины.
