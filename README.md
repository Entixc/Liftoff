# Workout Tracker

Веб-приложение для ведения дневника силовых и домашних тренировок.

Пользователь запускает тренировку, добавляет упражнения и подходы, затем сохраняет результат в истории. Полные требования MVP описаны в [docs/PROJECT_SPEC.md](docs/PROJECT_SPEC.md), а существенные технические решения — в [docs/DECISIONS.md](docs/DECISIONS.md).

## Стек

- Backend: Python, FastAPI, SQLAlchemy, Alembic, PostgreSQL
- Frontend: React, TypeScript, Vite
- Инфраструктура: Docker Compose

## Текущий статус

Готовы регистрация, вход, защищённый профиль, начальный каталог упражнений и полный цикл тренировки. Пользователь может вести активную тренировку, управлять упражнениями и подходами, завершить её, открыть в истории и отредактировать, включая время начала и окончания. Критичные backend-сценарии покрыты интеграционными тестами.

Интерфейс Liftoff использует графитовую тему с мягким зелёным акцентом, боковую навигацию на компьютере и нижнюю панель на телефоне. Основные действия проверяются браузерными тестами на desktop и мобильном размере.

## Экраны и управление

- **Главная:** начало или продолжение тренировки, таймер активной сессии, последние три записи истории и параметры профиля.
- **Тренировка:** выбор упражнения через поиск и категории; добавление подходов, изменение веса и повторений, отметка выполнения. Изменённый подход сохраняется кнопкой «Сохранить» или отметкой выполнения.
- **Удаление:** свайп строки влево открывает действие удаления. Для мыши и клавиатуры есть кнопка «…». Удаление всегда требует подтверждения; упражнение удаляется вместе со своими подходами.
- **История:** просмотр завершённой тренировки; кнопка «Редактировать» открывает изменение упражнений, подходов и времени. Время указано в часовом поясе устройства и сохраняется отдельной кнопкой. «Готово» закрывает режим редактирования.
- **Упражнения:** общий каталог с поиском по английскому названию и фильтрами категорий.
- **Профиль:** рост, вес, дата регистрации и выход. На телефоне профиль открывается через аватар в шапке.

После обновления страницы сохранённые данные восстанавливаются с сервера. Несохранённый ввод не является черновиком на сервере: перед переходом на другой экран нажимайте кнопку сохранения. При истечении токена приложение возвращает ко входу; ошибка сети сама по себе не удаляет сессию.

## Конфигурация

Скопируйте шаблон окружения, замените значения `CHANGE_ME` и укажите собственный `JWT_SECRET_KEY`:

```bash
cd /d/liftoff
cp .env.example .env
```

Для JWT создайте случайный секрет:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Настоящий `.env` игнорируется Git и не должен попадать в репозиторий. Если пароль PostgreSQL содержит специальные символы, в URL подключения их нужно кодировать: например, `@` заменяется на `%40`.

## Локальный запуск без Docker

Для backend нужны Python 3.14 и запущенный PostgreSQL. В Git Bash загрузите переменные из созданного `.env` и запустите приложение:

```bash
cd /d/liftoff
set -a
source .env
set +a

source .venv/Scripts/activate
cd backend
python -m pip install -r requirements.txt
python -m alembic upgrade head
python -m app.scripts.seed_exercises
python -m app.main
```

В другом Git Bash терминале загрузите то же окружение и запустите frontend:

```bash
cd /d/liftoff
set -a
source .env
set +a

cd frontend
npm install
npm run dev
```

Frontend обычно доступен по адресу `http://localhost:5173`, backend — по адресу `http://localhost:8000`, а документация API — `http://localhost:8000/docs`.

## Запуск через Docker Compose

После создания `.env` убедитесь, что `POSTGRES_PASSWORD` совпадает с паролем внутри `DOCKER_DATABASE_URL`, а адрес базы в этом URL использует хост `db`. Затем выполните:

```bash
docker compose up --build
```

Compose поднимет PostgreSQL, применит миграции, заполнит каталог упражнений и запустит backend и frontend.

## Проверка проекта

Backend:

```bash
cd /d/liftoff
set -a
source .env
set +a

source .venv/Scripts/activate
cd backend
python -m pytest tests
```

Frontend:

```bash
cd /d/liftoff/frontend
npm run build
```

Браузерные UI-тесты (первый запуск требует установки тестового Chromium):

```bash
cd /d/liftoff/frontend
npm install
npx playwright install chromium
npm run test:ui
```

Playwright самостоятельно запускает отдельный Vite-сервер на `127.0.0.1:4174`. Тесты подменяют ответы API; PostgreSQL и запущенный backend не нужны, реальные пользовательские данные не меняются. Они проверяют интерфейс и запросы, но не заменяют интеграционные тесты backend. Скриншоты и трассировки сохраняются в игнорируемой папке `frontend/test-results`.

Для единого форматирования React-кода: `npm run format`.

### Как устроен frontend

- `src/app.tsx` — сессия пользователя, загрузка общих данных и переключение экранов через URL после `#`.
- `src/components/AppShell.tsx` — шапка, боковая и мобильная навигация.
- `src/components/ui.tsx` — общие кнопки, поля, состояния, уведомления и диалог подтверждения.
- `src/components/WorkoutEditor.tsx` — один редактор упражнений для активной тренировки и истории.
- `src/components/WorkoutExerciseCard.tsx` — упражнения, ввод подходов и сохранение.
- `src/components/SwipeToDelete.tsx` — распознавание свайпа и доступная кнопочная альтернатива.
- `src/api/` — HTTP-запросы; `http.ts` обрабатывает истечение сессии.
- `src/styles.css` — палитра, компоненты и адаптивная раскладка.
